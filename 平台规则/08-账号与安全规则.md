# 账号与安全规则

按 `api/auth.py`、`api/admin.py`、`core/security.py`、`models/authx.py` 与
`models/extras.py`（找回密码令牌）实际实现书写。

## 一、注册

- `POST /auth/register`，必填**用户名 + 密码 + 邮箱**。
- 密码至少 10 位，且包含字母/数字/符号中的至少两类；注册与重置密码使用同一强度规则。
- 注册准入由 `platform_settings` 控制：
  - `reg.invite_only=true` 时必须填写有效邀请码；
  - 平台总管理员可在后台批量生成邀请码，选择数量、有效期与每码可用次数，也可单码或整批停用；
  - 邀请码核销与创建用户在同一事务中完成，PostgreSQL 下锁行防止一次性码被并发重复使用。
- 注册邮箱验证码代码已经预留。`EMAIL_BACKEND=smtp` 且 `SMTP_HOST` 已配置时，
  `reg.email_verify=auto/on` 才实际要求验证码；邮件尚未接通时注册**不要求验证**，
  接口也不会把验证码明文回传给浏览器。
- 唯一性：**用户名唯一**（"用户名已存在"）、**邮箱唯一**（"该邮箱已被注册"）。见 `10`。
- 显示名 `display_name` 缺省用用户名；**显示名允许重复**（唯一键是用户名/ID）。
- 新用户默认角色 `member`，注册即返回 access/refresh token。

## 二、登录与令牌

- 密码用 **argon2** 哈希（`PasswordHasher`）存储，绝不存明文。
- `POST /auth/login` 返回 JWT `access` + `refresh`（`create_access_token/refresh_token`，签名 `JWT_SECRET`）。
- `access` 携带 `sub`(用户id)/`type`/`jti`/`iat`/`issued_ms`/`exp`；
  `decode_token` 校验 `type=="access"` 才放行受保护接口。
- `POST /auth/refresh` 同时轮换 access 与 refresh；旧 refresh 的 `jti` 立即写入撤销表，
  不能重复使用。前端遇到普通接口 401 时只发起一次并发共享的静默刷新，成功后自动重放原请求。
- 重置密码、注销账号或“退出全部设备”会推进用户的令牌撤销时间，之前签发的 access/refresh 均立即失效。
- TTL 由 `JWT_ACCESS_TTL`/`JWT_REFRESH_TTL` 配置；access 保持 1 小时不会导致用户被动退出。
- 用户 `status=="left"` 视为已注销：登录、access token 与 refresh token 均拒绝。完整注销规则见 `14`。

## 三、找回密码

- `POST /auth/forgot-password`：按邮箱找到用户 → 生成一次性 `PasswordResetToken`（`secrets.token_urlsafe`）→
  经邮件抽象层（见 `07`）发 `SITE_URL/#/reset-password?token=` 链接。**邮箱不存在时不报错**（防枚举）。
- `POST /auth/reset-password`：凭未使用的 token 重置密码，用后置 `used=True`，并撤销该账号旧令牌。
- 登录、注册、验证码与找回密码接口均有限频；找回密码/账号名以及“已注册邮箱申请验证码”
  对匿名调用者返回统一表述，避免邮箱枚举。

## 四、鉴权下载的坑（工程约束）

需登录的下载接口（模板/导出/附件/skill/代码/版本文件/codebook/对照表等）**不能用 `window.open`**（不带 Bearer → 401）。
前端统一用 `utils/download.ts` 的 `downloadFile()`（axios blob + 拦截器带 token）。

## 五、资料与主页

- `PATCH /me`、`POST /me/avatar`、简历整块编辑 `PUT /me/resume/blocks`、在做项目 `POST /projects`（可置顶）。
- 全站按姓名/用户名/ID 检索用户：`GET /users/search?q=`。
- 用户资料、简历、头像和项目封面均要求登录；项目封面还复用 `scope_visible()` 校验可见范围。
- 头像与项目封面由前端 `AuthImage.vue` 通过带 Bearer 的请求加载，不使用匿名图片接口。

## 六、生产配置基线

- PostgreSQL 环境视为生产：`JWT_SECRET` 若为空或仍是默认值则拒绝启动。
- 生产默认关闭 `/docs`、`/redoc` 与 `/openapi.json`。
- `ALLOWED_ORIGINS` 留空时，生产只允许 `SITE_URL` 同源；Render 蓝图显式写入线上域名。
- `SEED_ON_START=false`，禁止自动创建 `admin/admin123` 等演示账号；首次部署用
  `BOOTSTRAP_ADMIN_*` 环境变量创建强口令总管理员。
